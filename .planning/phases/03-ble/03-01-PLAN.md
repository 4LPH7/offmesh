<objective>
BLE link layer behind `MeshTransport`: segmentation to ATT MTU, a radio seam, a shared
sealed handshake extracted from `LanLink`, a Kotlin radio, and a manual spike procedure.

Written before the Phase 3 spike (03-00) has produced data. The radio choice (platform
channel, no new pub package) and the MTU and chunk sizes are provisional until the spike
measures them on real phones.
</objective>

<scope>
In: REQ-19 (segmentation, MeshTransport over a radio seam), REQ-20 (dual-role radio
surface: advertise, scan, GATT server, GATT client), REQ-22 (rotating-ID advertisement
encoding).
Out: BLE peer manager (dial, dedupe, re-advertise per epoch), app wiring, foreground
service (REQ-21), runtime permission prompts, hardware verification.
Design only, recorded here: one BLE link per peer PeerID; the lower PeerID dials; the
advertisement changes with the hourly epoch.
</scope>

<tasks>
<task type="auto">
  <name>Task 1: Segmenter and reassembler</name>
  <description>
    `lib/core/ble/ble_segmenter.dart`: `segment(frame, mtu, messageId)` splits a sealed
    frame into chunks. Chunk data per write = mtu - 3 (ATT) - 4 (header: index u8, total u8,
    message id u16 BE). mtu must be 23..517. Frames over 512 bytes or needing more than 255
    chunks are rejected.
    `lib/core/ble/ble_reassembler.dart`: `BleReassembler(clock, timeout, maxInFlight 32)`;
    `add(chunk, maxChunkLength)` returns the frame when complete. Rejects short chunks, total
    0, index >= total and chunks over maxChunkLength (throws BleFramingException). Duplicate
    chunks ignored; total mismatch drops the partial; oldest partial evicted at the cap;
    partials older than timeout are dropped on each add.
  </description>
</task>
<task type="auto">
  <name>Task 2: Advertisement codec</name>
  <description>
    `lib/core/ble/ble_advertisement.dart`: flags AD (3 bytes) plus service data AD for a
    128-bit UUID (2 + 16 + 8 = 26 bytes): 29 bytes total, under the 31-byte legacy limit.
    `parseRotatingId` returns the 8-byte ID or null. Provisional UUID constant.
    Android builds the same structure through AdvertiseData (the stack adds flags); this
    codec is the tested reference and the parser for real scan bytes.
  </description>
</task>
<task type="auto">
  <name>Task 3: Shared sealed handshake</name>
  <description>
    Move the challenge, bound hello, role check, roster resolve, seal/open, keepalive and
    close logic out of `LanLink` into `lib/transports/sealed_link.dart` (`SealedLink`). It
    takes whole sealed frames via `onSealedFrame` and a `writeSealed` callback plus a
    `closeTransport` callback. `LanLink` keeps its exact public API and wire format and
    becomes a socket adapter. Existing LAN tests must pass without edits.
  </description>
</task>
<task type="auto">
  <name>Task 4: BleRadio seam, BleLink, fake pair tests</name>
  <description>
    `BleRadio` (advertise, stop advertise, scan, stop scan, sightings, inbound channels,
    connect as client) and `BleChannel` (mtu, isClient, received chunks, write chunk,
    close). `BleLink implements MeshTransport`: seals via SealedLink, segments at the MTU
    read at send time (23 until negotiated, or a forced MTU for tests), reassembles inbound.
    Tests use a fake channel pair in `test/transports/ble_fake_radio.dart`.
  </description>
</task>
<task type="auto">
  <name>Task 5: Android radio</name>
  <description>
    No new pub package. `flutter_blue_plus` documents central-role support; advertising and
    GATT server are not part of it (to be confirmed before 03-02). `BleRadioPlugin.kt` uses
    the framework: BluetoothLeAdvertiser, BluetoothGattServer, BluetoothGatt client, one
    method channel and one event channel. Kotlin moves bytes only, no protocol logic.
    Manifest: BLUETOOTH_SCAN (neverForLocation), BLUETOOTH_ADVERTISE, BLUETOOTH_CONNECT;
    legacy BLUETOOTH and BLUETOOTH_ADMIN with maxSdkVersion 30; ACCESS_FINE_LOCATION with
    maxSdkVersion 30. Runtime permission prompts are not in this plan; the plugin returns
    permission_denied.
  </description>
</task>
<task type="auto">
  <name>Task 6: Spike document</name>

    a go/no-go table. Status: NOT RUN.
  </description>
</task>
</tasks>
