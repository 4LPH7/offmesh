<objective>
Store-and-forward building blocks for Phase 5: a one-way encryption mode, a custody envelope with a
recipient hint, an expiry and a copy budget, and a memory-only store with spray and ID exchange
arithmetic. Pure Dart, tested with unit tests. No transport carries these yet.
</objective>

<known_limits>
- No forward secrecy in K. Compromise of a recipient's static key opens every envelope sealed to it.
- No sender identity beyond the initiator's static key. The sender is found by trying roster keys.
- Recipient hint: each envelope names its recipient by PeerID in clear inside the envelope. Carriers
  are unit members that already read sealed headers under the unit seal key (docs/mission_plan.md
  4.5), so carriers learn the recipient. An outsider without the unit key does not, because the
  envelope travels inside sealed link frames.
- Replay: the store and the delivered-once log stop repeat copies. There is no other replay check.
- Frame size, open: a 547-byte envelope plus a 1-byte kind and the 28-byte seal is 576 bytes, over
  maxFrameLength (512 in lan_frame.dart). Envelopes must be fragmented (fragmentation.dart carries
  220-byte payloads), or the ciphertext cap lowered so a sealed envelope fits 512 bytes. An ID list of
  256 ids is 4098 bytes and must be chunked too.
- Not wired: the store is owned by nothing. The contact exchange, the posture check (nothing
  transmits in Silent, and Quiet holds sends), and the panic-wipe clear need a later plan.
- Spray split is committed before the send is confirmed. A link that dies mid-send loses those copies.
- A delivered envelope stays held at the carrier until it expires. Only the recipient's advertisement
  stops re-sends.
- Clock: creation times up to 10 minutes in the future are accepted, so expiry can drift by that much.
</known_limits>
