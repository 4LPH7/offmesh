<design>
- Posture: `enum Posture { silent, quiet, normal }` and `PostureController` in
  lib/core/posture.dart, with no store import. `LanManager` owns the controller
  (`lan.posture`) and `ChatController` reads it from there, so there is one instance.
- Persistence: lib/app/posture_store.dart writes `posture.v1` through SecretStore. Absent
  loads as Normal. An unknown value or any read error loads as Silent (fails closed).
- Choke points in LanManager:
  - `start()` refuses in Silent and is idempotent while listening.
  - `connect()` refuses in Silent.
  - `_adopt()` destroys a socket that arrives in Silent.
  - `_sendBeacon()` checks the posture again after sealing, so a switch during sealing still
    stops the send.
  - `_onBeacon()` returns unless Normal. After the two-interval delay it checks again, so a
    dial already waiting does not fire after a switch to Quiet.
- Restart paths: `ChatController.start()` loads the posture before the first LAN start.
  `_startLan()` is the single LAN start path and skips in Silent. Create, add-member and
  import all go through `_install`, which uses it.
- Silent sending: `send()` returns before `node.sendText`. MeshNode would queue the message
  per peer and flush it when a link returns.
- Quiet: `send()` holds the message with `queued: true` and no packet ID. `sendBurst()`
  sends the held messages in order. A message the node refuses goes back on the queue.
- Quiet keepalives: links that are already open keep their keepalive (every 10 s) and their
  receipts and relays. Quiet means no beacons and no beacon-triggered dials, not a silent
  link.
- Ordering: `setPosture` changes the in-memory gate first, then the radios, then saves.
  A failed save is reported and the session keeps the new posture.
- Panic wipe: `ChatController.panicWipe()` deletes `storedSecretKeys` (unit, identity,
  posture) first, then stops every transport inside a try/catch, so a transport error cannot
  hide the result or stop the deletes. A failed delete does not stop the other deletes; the
  wipe reports failure and the unit is kept for a retry, with transports still stopped. On
  success it clears messages, members and identity fields. The root widget (main.dart) disposes the wiped
  controller and calls `buildController` again, so the new identity comes from the
  store, not from the wiped node.
- Double confirmation: the Panic wipe button opens a dialog. The Wipe button is enabled
  only when the field reads WIPE.
- Relay Mode: `RelayScreen` sets the posture to Normal on entry, shows relaysSent,
  relaysSuppressed and link count, polls once a second, and cancels its timer on dispose.
</design>
