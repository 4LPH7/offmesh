<objective>
Close Phase 1: key separation, replay freshness for sealed frames, and decoder fuzzing.

Purpose: one captured key must not serve two purposes, a recorded frame must not be
replayable after the seen cache forgets it, and no malformed input may crash a node.
Output: `unit_keys.dart`, a freshness check in `sealed_envelope.dart`, and three test files.
</objective>

<tasks>
<task type="auto">
  <name>Task 1: Derive seal key and ID key</name>
  <description>
    `UnitKeys.derive(unitSecret)` returns a 32-byte seal key and a 32-byte ID key using
    `Hkdf` from package:cryptography with labels `offmesh/seal/v1` and `offmesh/id/v1`.
    Validate the unit secret length (at least 32 bytes). Test against values computed
    independently in the test, and assert the two keys differ from each other and from the input.
  </description>
</task>

<task type="auto">
  <name>Task 2: Freshness timestamp inside the seal</name>
  <description>
    Prefix the plaintext with a 4-byte big-endian Unix-seconds timestamp from an injected
    clock before sealing. `open` rejects frames whose timestamp is outside a window
    (constant, default 10 minutes each way) with `SealedEnvelopeException`. Update
    `sealOverhead`. Tests: fresh frame opens; frame older or newer than the window fails;
    boundary values; existing tamper tests still pass.
  </description>
</task>

<task type="auto">
  <name>Task 3: Decoder fuzz test</name>
  <description>
    One test file with a seeded `Random`. For `Packet.decode`, `SealedEnvelope.open`,
    `Reassembler`, and `DeliveryReceipt` decode: start from valid encodings, apply random
    truncation, extension, and byte flips, 100,000 inputs in total. Any exception other
    than the decoder's own typed exception fails the test. Follow the seeded-spray pattern
    in `test/core/mesh/mesh_limits_test.dart`. No new dependency.
  </description>
</task>

    If yes, it becomes its own plan; do not build it here.
  </description>
</task>
</tasks>
