<objective>
Persistent identity. Today `lib/main.dart` calls `Identity.generate()` on every launch, so a
phone's PeerID changes each time it starts, which makes rosters and contacts useless.

Output: a small secret-store seam with one production implementation over
`flutter_secure_storage` and one in-memory implementation for tests, plus
`IdentityStore.loadOrCreate` used by `main.dart`.
</objective>

<scope>
In: REQ-12 only. The store exposes a generic key/value API for bytes, so 02-02 can add the
unit secret and roster without changing it.
Out: unit secret, roster, refusing to link when unprovisioned (REQ-13, plan 02-02),
panic wipe (REQ-24, Phase 4).
</scope>

<tasks>
<task type="auto">
  <name>Task 1: Secret store seam</name>
  <description>
    `abstract interface class SecretStore { Future<Uint8List?> read(String key); Future<void> write(String key, Uint8List value); Future<void> delete(String key); }`.
    `PlatformSecretStore` wraps `flutter_secure_storage` (base64 values; Android options
    that use Keystore-backed encryption). `MemorySecretStore` for tests. Add the dependency
    with `flutter pub add flutter_secure_storage`; check its Android minSdk and Windows
    support, and raise `minSdk` in android/app/build.gradle(.kts) only if required.
  </description>
</task>

<task type="auto">
  <name>Task 2: Identity from stored seed</name>
  <description>
    `Identity.fromPrivateKey(List<int> seed)` (32 bytes, validated) and a way to export the
    private seed for storage. `IdentityStore.loadOrCreate(SecretStore)` reads key
    `identity.x25519.v1`; absent → generate, write, return; present and 32 bytes → rebuild;
    present and wrong length → throw `IdentityStoreException`. `main.dart` uses it and shows
    a minimal error screen if it throws.
  </description>
</task>

<task type="auto">
  <name>Task 3: Tests</name>
  <description>
    Second `loadOrCreate` on the same store returns the same PeerID and public key; a fresh
    store gives a different identity; a malformed stored value throws and is not
    overwritten; the rebuilt key pair completes a Noise XX handshake with a peer (proves the
    private half survived, not only the public key).
  </description>
</task>
</tasks>
