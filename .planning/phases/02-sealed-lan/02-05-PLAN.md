<tasks>
<task type="manual">
  <name>Task 1: Procedure</name>
  <description>
    Numbered steps in docs/device_tests.md: prerequisites (APK, Windows build, Npcap,
    firewall, clocks within 10 minutes, a fixed marker string `zqx7` in every message),
    unprovisioned devices cannot link, provisioning with the PC as unit creator so the
    unit secret is only ever scanned from a screen and never moved as text, fingerprint
    comparison by eye, linking by beacon with manual IP and port as fallback, the message
    counts with delivered marks, restart of B and of the PC, optional non-member check.
    The TCP listen port is ephemeral, so each device's "Listening on port N" is recorded
    after every start.
  </description>
</task>

<task type="manual">
  <name>Task 2: Capture checklist</name>
  <description>
    Filters C1 to C6 (beacons present, beacon payload exactly 42 bytes, PC links present,
    no `OFFM`, no static PeerID bytes, no marker text), C7 (no repeated beacon payload,
    via tshark), C8 (Follow TCP Stream shows nothing readable). States what the PC
    capture cannot see (the A-to-B link) and what is visible by design.
  </description>
</task>
</tasks>

<known_limits>
- Not yet run. The results table is empty.
- The Windows app does not build on the development machine (missing Visual Studio ATL
  headers for flutter_secure_storage_windows). The PC leg needs a build from a machine
  with that component.
- The ROADMAP says "20 between B and the PC". The procedure sends 20 each way, which is
  stricter and satisfies either reading.
- The PC, as an ordinary Wi-Fi client, cannot capture the A-to-B TCP link. Criterion 3 is
  checked on all beacons and the PC's own links.
- Criterion 4 (rotating ID changes each hour) cannot be observed on the wire, because the
  ID is inside the seal. It rests on unit tests.
- Android may not deliver broadcast datagrams to the app; the procedure has a manual
  connect fallback and records when it was used.
- Moving identity codes to the PC needs a channel (USB cable suggested). They hold only a
  public key and a name.
