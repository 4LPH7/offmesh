<objective>
Delivery receipts in the UI. Phase 1 already sends and checks end-to-end receipts (a Noise
transport message from the recipient), and MeshNode.sendText already returns the packet ID
the receipt will carry. The app drops them. After this plan, each sent message shows a sent
mark, and the mark changes to delivered when the matching receipt arrives. The README is
brought in line with the running app.
</objective>

<task type="auto">
  <name>Task 1: Track receipts in ChatController</name>
  <description>
    `ChatMessage` gains `packetId` (int?, outgoing only) and `delivered` (bool, default false).
    `send()` stores the ID that `node.sendText` returns. `start()` subscribes to
    `node.receipts` with a public `handleReceipt(DeliveryReceiptEvent)`, mirroring
    `handleIncoming`; `stop()` cancels it. `handleReceipt` looks only in the thread of
    `event.peerId`, finds the outgoing, undelivered message with the same packet ID, and
    replaces it with a delivered copy (no mutation), then notifies. Anything else is ignored.
  </description>

<known_limits>
- "Delivered" means the recipient's node decrypted the message, not that a person read it.
- Marks live in memory with the messages and are lost on restart.
- No retry: a message whose receipt never arrives keeps its sent mark.
- A receipt that arrived before `send()` recorded the message would be ignored. It needs a
  full round trip plus Noise decryption on the far side, so it has not been seen in tests.
</known_limits>
